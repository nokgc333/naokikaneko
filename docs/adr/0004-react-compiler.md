# ADR-0004: React Compiler を有効にしたままにする

- 状態: 採用（プロジェクト作成時から有効。2026-10 に計測して継続を確認）
- 関連: `next.config.ts`（`reactCompiler: true`）、`babel-plugin-react-compiler`

## 背景

React Compiler は、コンポーネントのメモ化を自動で行う。Next.js 16 のプロジェクト作成時の選択肢にあり、このリポジトリでは最初から有効だった。採用時に判断の記録を残していなかったため、継続するかどうかを計測で確認した。

## 計測（2026-10-25、本番ビルド）

| | クライアント JS の合計 | `next build` のコンパイル |
|---|---|---|
| `reactCompiler: true` | 792,132 B | 673 ms |
| `reactCompiler: false` | 786,754 B | 1,384 ms（ばらつきあり） |

バンドルの大きさの差は 0.7% で、ビルド時間の差は計測のばらつきの範囲。つまり、コストは見当たらない。

## 決定

有効のままにする。手書きの `useMemo` / `useCallback` を書かずに済み、コンパイラの規則に反するコードは、ESLint（`react-hooks` の規則）が検出する。

## 結果

- 良い: メモ化を意識せずに書ける。規則違反を CI（lint）で止められる。
- 悪い: ビルドに Babel のプラグインが入る。バグがあったときの切り分け先が一つ増える。
- 計測していないもの: 実行時の再描画の減少量。このサイトは更新の少ない静的ページ中心で、効果は小さい見込み。

## 見直す条件

コンパイラが原因の不具合が出た、またはビルドが遅くなった場合は、`reactCompiler: false` に戻す（設定 1 行）。戻しても、動作は変わらない（計測で確認済み）。
