# ADR-0006: 性能は Lighthouse CI の予算で守り、日本語フォントは差し替えない

- 状態: 採用（2026-10-25）
- 関連: `.lighthouserc.cjs`、`src/app/layout.tsx`、`.github/workflows/ci.yml`

## 背景

「速い」ことを見せるサイトなので、性能が劣化したら CI で止めたい。一方、日本語のサイトでは、Web フォント（Noto Sans JP）が転送量とレイアウトのずれ（CLS）の原因になる。

## 決定

- Lighthouse CI（`@lhci/cli`）で、主要 5 ページ（トップ・About・ブログ一覧・ブログ記事・Work 詳細）を各 3 回計測し、予算を超えたら CI を失敗させる。
  - トップ: 性能スコア 0.9 以上、LCP 2.8s 以内、JS 195KB 以内、総転送 410KB 以内
  - 他のページ: スコア 0.75 以上、LCP 5s 以内、総転送 1.4MB 以内
  - 全ページ: CLS 0.1 以下、TBT 200ms 以下
  - 予算は、実測に余裕を足した値。改善したら引き下げる。
- フォント: Roboto（ラテン文字）は `display: swap`。Noto Sans JP は `display: optional`（表示後に差し替えない）で、先読みしない。等幅フォントも先読みしない。
- スキップリンクなど、画面に出る文言を日本語にすると、ホームでも日本語フォントのスライス（約 80KB）を取りに行く。そのため、ホームに出る補助的な文言は英語にする（`lang="en"` を付ける）。

## 根拠（計測、ローカル、モバイル模擬回線）

- ホーム: 性能 0.91 → 0.96〜0.97、LCP 3.5s → 2.6〜2.7s、未使用 JS 101KiB → 29KiB。
- 効いたもの: zod をホームの JS から外す（フィルターが zod を含むスキーマから定数を読んでいた）、フォームの遅延読み込み、先頭画像の優先読み込みと `sizes`、フォントの先読みの削減。
- 効かなかった／採用しなかったもの: `experimental.inlineCss`（HTML が 12KB → 599KB に膨らみ、FCP も LCP も悪化）、DaisyUI の削除（CSS は半分になるが LCP は変わらず、本文の色が変わる）。
- CI（Linux）で CLS が予算を超えた。日本語の代替フォントがないランナーで Web フォントの差し替えが起きたため。`display: optional` に変えて解消し、CI の性能予算ジョブで確認した。

## 結果

- 良い: 性能の劣化が PR で見つかる。予算の根拠が記録されている。
- 悪い: LCP は目標の 2.5s に届いていない（2.6〜2.7s）。About・ブログ記事は日本語フォントのため、総転送が 0.6〜1.2MB になる。
- `@lhci/cli` の推移的依存で、開発依存の `npm audit` の指摘が増える（本番依存には影響しない）。

## 見直す条件

LCP を縮めるには、見た目に関わる判断（DaisyUI の見直し、日本語フォントの扱い）が要る。その判断をしたら、予算を引き下げる。
